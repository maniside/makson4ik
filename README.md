# Вариант 9. Бронирование помещений

Базовый уровень, Java 21, Maven, JUnit 5. Приложение консольное.
Данные создаются в Main, в файлы и базу данных не сохраняются.
Повышенный уровень (повторяющиеся брони и перенос) не реализован.

## Запуск в IntelliJ IDEA

1. Открыть папку room-booking или её pom.xml как Maven-проект.
2. Дождаться загрузки Maven-зависимостей.
3. Выбрать JDK 21 или новее в Project SDK. В pom.xml указан release 21:
   исходники компилируются для Java 21, даже при сборке более новым JDK.
4. Открыть src/main/java/ru/study/booking/Main.java и нажать зелёный треугольник у main.
   Также доступна конфигурация «Бронирование помещений».
5. Для тестов открыть src/test/java/ru/study/booking/BookingServiceTest.java
   и запустить класс зелёным треугольником.

Команды из папки проекта, если Maven доступен в PATH:

```text
mvn verify
java -jar target/room-booking-1.0-SNAPSHOT.jar
```

При первом запуске Maven нужен интернет для JUnit и плагинов сборки.
Сторонних библиотек в основном приложении нет.

## Классы

| Файл | Назначение |
| --- | --- |
| Main | Заполняет модель и последовательно показывает операции |
| Room | Неизменяемое помещение: номер, название, вместимость, тип, оборудование |
| Employee | Неизменяемый сотрудник: номер и имя |
| TimeInterval | Начало и конец интервала, проверка корректности и пересечения |
| Booking | Номер брони, помещение, сотрудник и интервал |
| RoomType | Перечисление типов помещений |
| Describable | Общий интерфейс с методом describe |
| BookingConflictException | Собственное исключение при занятом времени |
| BookingService | Хранит помещения и брони, выполняет операции |

Room и Employee по-разному реализуют describe. Main вызывает этот метод через
общий тип Describable: это демонстрация полиморфизма.

Модели-значения объявлены как record: Java создаёт закрытые final-поля, методы
чтения и согласованные equals/hashCode по всем компонентам записи.
Например, сотрудники равны, если совпадают и номер, и имя.
Уникальность номера помещения отдельно проверяется в BookingService.

В Room входной набор оборудования копируется через Set.copyOf.
BookingService возвращает List.copyOf, поэтому внешний код не может изменить
внутренние списки. Элементы этих списков также неизменяемы.

## Операции базового уровня

- book: проверяет помещение и пересечения, создаёт бронь.
- cancel: удаляет бронь по номеру, возвращает результат отмены.
- freeWindows: возвращает свободные промежутки помещения за выбранный день.
- findRooms: подбирает свободные помещения с вместимостью не меньше заданной.
- isAvailable: вспомогательная проверка доступности.

Интервал задаётся через LocalDateTime и обозначается [начало, конец).
Бронь 09:00-11:00 не мешает брони 11:00-13:00.
Формула пересечения: начало первого раньше конца второго И
начало второго раньше конца первого.

Для свободных окон день считается полными сутками: от 00:00 до 00:00 следующего дня.
Занятые интервалы сортируются по началу. Затем программа идёт от начала дня,
добавляя промежутки между бронями. Брони через полночь обрезаются границами дня.

Вместимость учитывается при подборе. У брони нет числа участников:
в варианте это поле не задано. Ограничение занятости сотрудника не вводится,
так как проверка требуется именно для помещения.

## Демонстрация

Создаются 10 помещений, 10 сотрудников и 20 броней: всего 40 объектов модели,
не считая объектов времени. Затем выводятся конфликтная попытка,
свободные окна, подбор помещений, отмена и повторная бронь освободившегося времени.
Дата фиксированная, поэтому результат не зависит от дня запуска.

## Тесты и документация

26 тестов JUnit 5 проверяют операции, соседние и пересекающиеся интервалы,
полностью занятый и пустой день, переход через полночь, ошибочные данные,
защитное копирование и контракт equals/hashCode.
Для ожидаемых исключений используется assertThrows.
На публичных методах модели есть Javadoc; параметры record описаны на уровне записи.

Генерация HTML-документации из папки проекта:

```text
javadoc -encoding UTF-8 -charset UTF-8 -d target/apidocs -sourcepath src/main/java ru.study.booking
```

## Git

В проекте есть локальный Git-репозиторий с отдельными коммитами этапов:
модель, операции, демонстрация, тесты, документация.
Коммиты выполнены в ходе одной сессии, их даты не менялись.
Это не подтверждает работу в течение учебного срока: дальнейшие самостоятельные
изменения стоит сохранять отдельными осмысленными коммитами.
Автор технических коммитов указан как Student <student@localhost>.
Перед собственными последующими коммитами задайте своё имя и почту локально в Git.
Удалённый репозиторий не создан.
